## 1. 機能の概要

プレイヤーは8犬種から相棒を選び、その犬と背後視点の3Dコースを走る。スマートフォンの縦持ちを中心に設計しており、PCのキーボードでも操作できる。犬種・毛色・スカーフは見た目の選択で、同じ入力なら同じ走行規則で競技する。

1. 通常の入口を開くと「相棒を選ぶ」。初回はポメラニアン・オレンジ・青スカーフ。犬を回して眺め、犬種、毛色、スカーフを変更できる。
2. 「モード選択へ」で「レース」または「アジリティ」を選び、「コース選択へ」。前に確定したモードと、モード別に確定したコースがあれば復元する。
3. コースカードで立体プレビュー・難易度・自己ベストを確認。「このコースで走る」でスタート画面へ。「走る」を押したあと3秒のカウントダウンで自動前進を始める。
4. **レース**は相棒とCPU4匹の競走。左右移動・右左折・ジャンプ・ブレーキで障害物を抜け、おやつ20個をためて好きなタイミングでタップし、3秒間ダッシュする。ゴールで順位と5匹全員のタイムが決まる。
5. **アジリティ**は犬1匹で芝生の広場の器具6つを順に巡るタイム競技。左右移動・ジャンプ・停止・再開で器具を通る。ミスしても走り続けられ、1ミスにつき5秒を加える。犬を停止させて待っている時間も競技時間に入る。
6. どちらも一時停止・アプリ離脱で競技時計を止められる。完走後は自己ベストとの比較を見て、「もう一度」、同じモードの次コース、またはコース選択を選ぶ。最後のコースからは一覧へ戻る。通常入口を後日開くと相棒と記録はそのブラウザに残る。

### 3.3 視覚・画面サイズ・開発用の比較画面

犬は画風案A「ころころ3D」の丸い輪郭と柔らかな陰影、コースはC「すっきりポリゴン」の整理した色面を使う。立ち耳・巻き尾の柴犬、丸い巻き毛と垂れ耳のプードル、首毛からスカーフを見せるポメラニアンなど、選択画面と走行中の後ろ姿で識別できること。公園のおやつは両端に切れ込みと中央に肉球の焼き印のある骨型ビスケット。HUDアイコンと3D形状は共通の輪郭を使う。公園は芝・樹木と曲がり角、海辺は波・砂・パラソル、森は針葉樹・白樺と倒木。アジリティは外周の柵内に色調の異なる芝生と器具を置く。走行中は常に背後視点で、全景は選択時のプレビューに使う。

縦画面では画面上端と下端にHUDを寄せ、犬、直前の障害物、先の進路を同時に見せる。`viewport-fit=cover`、`100dvh`、4辺の `safe-area-inset-*` を利用。幅780px・高さ680px等で表示を詰め、幅360／375px前後、低い横画面にも調整がある。CSSは `style.css` の後に `partner-park.css` を読む。結果の自己ベスト欄は上下8px、高さ680px以下で上下6px、左右12px。プレビューの説明文やバージョンラベルには意図的に `hidden` の要素もある。

比較用 `review/index.html` は「犬選び」「最初の丸太」「最初の右折」等のシーン切替に加え、犬種、正面寄り・横・後ろ、変更前版を選べる。広い画面は2枚並列、幅660px以下は前後の版をボタンで入れ替える。トンネル入口・出口、横移動・壁接触は同期再生できる。一部は静止画の比較も開ける。固定フレームのために独立した子ページで時刻・入力・ストレージを差し替える。通常プレイの親ページに `review/clock.js` を読み込まない。

## 4. データ

### 4.1 永続化する全項目

保存先はゲームのDocumentが属するオリジンの `localStorage`。値はすべて文字列。JSON欄だけ `JSON.stringify`／`JSON.parse` を使う。データベース、Cookie、アカウントIDは使わない。

| キー | 文字列の中身・型 | 初期値と更新時点 |
|---|---|---|
| `wan-run-dog` | JSON object。`breed: string`（犬種ID）、`coat: number`（整数0〜2）、`scarf: string`（色ID） | 未保存時は `{"breed":"pomeranian","coat":0,"scarf":"blue"}` 相当。実際の書込は犬種確定、毛色選択、スカーフ選択、モード選択へ進む時。犬種候補を押しただけでは書き込まない |
| `wan-run-mode` | 生の文字列 `race`／`agility` | 未保存は確定モード `null`、画面上の候補は `race`。モード確定、または有効な `?play=` を開いた時に保存 |
| `wan-run-courses` | JSON object。任意の `race`・`agility` プロパティに各モードの有効なコースID文字列 | 初期は確定値なし。候補は `park` と `first-field`。コース開始の確定、次のコース、直行リンクでモード別に書き込む。カード仮選択・ページ送りは未確定 |
| `wan-run-best-park-turns-v1` | `park` の最短走行秒を数値文字列で保存 | 記録なし。公園の初完走から |
| `wan-run-best-beach-v1` | `beach` の最短走行秒 | 記録なし |
| `wan-run-best-forest-v1` | `forest` の最短走行秒 | 記録なし |
| `wan-run-best-first-field-arena-v2` | `first-field` の最短合計秒 | 記録なし。末尾 `arena-v2` を保持 |
| `wan-run-best-zigzag-v1` | `zigzag` の最短合計秒 | 記録なし |
| `wan-run-best-balance-v1` | `balance` の最短合計秒 | 記録なし |
| `wan-run-best-hill-field-v1` | `hill-field` の最短合計秒 | 記録なし |

`coat` は犬種配列内の添字で、色名や16進カラー値は保存しない。犬種IDが未知ならポメラニアン、添字が整数0〜2以外なら0、スカーフが未指定・未知・旧自動色なら青。犬種と毛色の無効判定は独立する。JSONの読込失敗や読み取り拒否は既定値へ戻る。無効なモードは未確定、別モードのコースIDや未知のコースはそのモードの先頭候補へ戻る。

自己ベストの読込条件は `Number(value)` が有限かつ正。空、0、負、非数、無限は未記録。`setItem` 失敗時はコース別の一時 `Map` に保持し、読み戻せる値と一時値の小さい方を返す。画面は「今回のベスト」と表示する。次回完走時、一時値があれば遅い結果でも保存を再試行する。相棒・モード・コースは保存拒否時にも現在のメモリ上の選択を使う。走行途中、5匹の全履歴、スカーフごとの別記録は保存しない。

## 5. 主要ロジック

### 5.1 入力を競技操作に変換する

| 入力 | 認識条件 | レース | アジリティ |
|---|---|---|---|
| 左／右スワイプ、←／→ | 水平成分の絶対値が垂直より大きい | 通常は1レーン移動。角の有効区間は右左折を優先 | 通常は1レーン移動。スラローム内は1回で指定側に移る |
| 上スワイプ、↑ | 縦が優勢で上向き。縦横が等しいときも縦を採用 | 地上からジャンプ | 停止中・器具拘束中を除きジャンプ |
| 下スワイプ、↓ | 縦が優勢または同じで下向き | 残り0.6秒のブレーキを設定。再操作で再設定 | 犬を停止。シーソー中央なら保持フェーズに入る |
| タップ、Space | ポインターはリリース時。共通のアクション名は `dash` | ゲージ20、発動中でない、角待ちでない時に消費 | 停止中の犬を再開。板の待機・傾斜中は無効 |
| Esc、一時停止ボタン | ゲームキーはCanvasにフォーカス。ボタン上の通常操作は優先 | カウントダウンまたは競技を一時停止 | 同左 |

ポインターは主ポインター1本だけを `pointerdown` 時に捕捉。開始位置からの `dx,dy` をCSS pxで測る。主軸距離 `major=max(abs(dx),abs(dy))` が28以上ならスワイプ。海辺と丘の広場に限り、210ms以下・`major≥20`・`major≥1.4×minor` の全条件で短いフリックも認識する。スワイプは移動中に成立した時点または指を離した時点で1回だけ送る。操作がゲーム側で却下されても同じポインターを再利用しない。タップは直線距離12未満、350ms未満、かつ途中でも12以上動いていない場合。条件の隙間に入るジェスチャーは無操作。キャンセル・捕捉喪失・一時停止では保留ポインターを破棄。矢印・Spaceのキーリピートを無視する。

### 5.2 時間、移動、当たり判定の共通部分

1. `requestAnimationFrame` ごとに `dt=clamp((t−last)/1000,0,0.2)`。初回は0。`n=max(1,ceil(dt/0.05))` 個の等しいサブステップに分ける。各 `step(dt)` は有限で `0<dt≤0.1` の時のみ更新。停止・非表示だった壁時計の差分をまとめて進めない。低フレームレートで0.2秒を超えた部分は競技時計にも加えない。
2. `ready→countdown→running→finished`。`start()` は `ready` のみ、`pause()` は `countdown,running` を記憶、`resume()` は記憶した状態に戻す。カウントダウンが0に届いたステップでは `go` を発行して終了。走行時だけ `time+=dt`。アジリティの `stopped` や曲がり損ねは `running` のまま。
3. 通常の左右入力は目標レーンを `[-1,1]` に制限し、`x(t)=target+(x0−target)×exp(−13t)` で滑らかに追従。競技共通のジャンプは `0≤t<0.94` で `1.55×sin(πt/0.94)`、飛んでいない時・終了時は0。二段ジャンプなし。
4. 基準点 `gate` を `s0 < gate ≤ s1` でまたいだ時、`τ=dt×(gate−s0)/(s1−s0)` を計算。サブステップ開始時の `x,jumpElapsed` を使い、`τ` 時点の横位置・高さ・接地を再計算。トンネル側壁に当たった後の同ステップのゲートでは遮られた方向を壁面でクランプする。フレーム終点の姿勢だけで障害物を採点しない。プレイヤーのおやつ取得には5.3の別の範囲判定を使う。
5. ゴールをまたぐフレームのタイムは `timeBefore + dt×(length−s0)/(s1−s0)`。位置をコース長に合わせる。画面の進行割合は `min(100,100×s/length)`、アクセシビリティ値は整数丸め。HUDは累積0.08秒超またはカウントダウン中に更新し、海辺のカーブ合図は走行フレームでも更新する。

### 5.3 レース

**前進と速度。** 各ステップの先頭で減速・ブレーキ・ダッシュの残秒を `max(0,残秒−dt)` にする。角待ちの相棒は速度0。通常は `v=(boost>0 ? 16.2 : 選手の通常速度) × 砂地倍率 × 衝突倍率 × ブレーキ倍率`、`s+=v×dt`。砂地倍率は海辺で `y<0.2` かつ `((s−砂地s)/4.8)² + ((x−2×砂地lane)/0.87)² <1` なら0.8、衝突倍率は `slow>0` なら0.43、ブレーキ倍率は `brake>0` なら0.63。それぞれ他の場合は1。衝突で `slow=1.15` に設定する。これらの倍率は併用される。

**曲がり角。** 各角は入口32手前から終点まで合図が出る。20手前から方向入力を受理する。予告のみの区間の左右は通常のレーン移動。受付中、正しい向きでその角のIDを予約し、中央レーンを目標にして待機を解く。逆方向は正解の向きを示して終了。予約済みの角は終点まで左右入力を重ねても再予約・横移動しない。未予約で入口に達したら `s=start` で止めて待つ。時計とCPUは進む。その角のミス数は一度だけ加算し、正しい左右入力で復帰。終点通過で `passedTurns` に1回加える。レースのミスに固定の加算秒はない。

**障害物。** 基準点で横距離が丸太は1.12未満、その他は0.72未満の場合に高さ判定。丸太は `y<0.68`、ハードルは `y<0.74` で衝突、トンネルは `y>0.55` で衝突してジャンプを解除。幅外なら障害物を横からかわす。公園の `hurdle` のうち `id%4===0` は見た目が丸太でも採点はハードル。各選手の `lastHitObstacle` と同じIDなら重複カウント・減速延長を行わない。

**公園トンネル。** 半径1.70、全長7.6、中心の描画オフセット1.25。判定区間は器具中心の−5.05から+2.55。中心から横1.16以内を内部とし、外面の当たり位置は1.96。進行区間と横移動の軌跡を交差判定し、内側から壁に当たると内面、外から当たると外面に戻す。側壁は同じ器具の中央ゲートと重複カウントを避ける。トンネル内では新しいジャンプは禁止、左右移動は可能。最外レーンからさらに壁方向へスワイプした場合も `wallReach` で壁接触を調べる。入口手前／出口後の通常移動と屋根の外を通る動きも許容する。

**おやつとダッシュ。** 相棒の取得条件は未取得IDで `previousS≤treat.s+0.4`、`newS≥treat.s−0.4`、`abs(x−lane×2)<0.72`、`abs(y+0.65−treat.y)<0.8`。全条件が成立すると累計を1増やし、`gauge=min(20,gauge+1)`。取得したインスタンスだけを隠す。満タンでも累計個数は増え続ける。プレイヤーはタップ／Spaceでゲージを0にし、`boost=3`、発動回数を1増やす。ブースト中もおやつを拾えるが再発動はできない。

**CPU。** 通常目標レーンは `[-1,+1,0,-1]`、曲がり角の20手前から角終点までは中央。障害物が先4.3未満、横距離0.65未満、ハードル／丸太で地上なら、`(obstacle.id+3×CPU添字)%7≠0` のとき自動ジャンプする。角の入力待ちはCPUに適用しない。指定されたライバルは各自の `nextTreat` から `s` 順に追跡し、通過時の `x,y` で横0.72未満・高さ差0.8未満を判定。相棒や別のCPUと独立に同じ取得物を拾える。20個でブーストが切れていれば自動発動する。

**順位と結果。** 走行中は `1 + count(CPUがゴール済み または CPU.s>相棒.s+0.02)`。相棒ゴール時点でCPU4匹の状態を複製し、未着の犬だけを同じ物理で1/60秒ずつ完走まで計算。元のシーン・相棒時計はゴール位置・ゴール時刻に保つ。`[相棒, cpu0, cpu1, cpu2, cpu3]` を内部の未丸めゴール秒で昇順ソートし、相棒の行番号が最終順位。完全同秒は安定ソートの入力順。表示は小数2桁で、見かけ上同タイムでも並びは内部値で決まる。

### 5.4 アジリティ

通常速度11.25、スラローム8、シーソー上4.2。ミスで `slow=0.65` 秒に設定し、その間は速度を0.65倍にする。停止中は進行距離を足さない。器具の通過は `results.has(id)` で一度だけ採点。成功は `cleared++`、失敗は `faults++, player.hits++`。いずれも次の未採点器具が誘導の対象となる。ゴールでは `penalty=5×faults`、`total=time+penalty`。全6器具をミスしても完走できる。

| 器具 | 採点時点・成功条件 | 失敗理由／操作制限 |
|---|---|---|
| ハードル | 中心通過時、横距離0.72未満かつ `y≥0.74` | 横を通ると「ハードルの横を通過」、高さ不足は「ジャンプが届かず」 |
| 輪っか | 中心通過時、横距離0.72未満かつ `0.7≤y≤1.6` | 「輪っかの横を通過」または「ジャンプが届かず」 |
| トンネル | 入口 `s器具−3`・出口 `s器具+3` それぞれで横距離0.72未満かつ `y<0.55`。入口の真偽を記憶し、出口で両方成立なら成功 | 入口失敗を先に表示。入口が有効で出口失敗なら「トンネルの出口を外れた」。中心前後3.4未満・横距離0.8未満では左右とジャンプを抑止。停止・再開は可 |
| スラローム | 列ごとに6本。第 `i` 本（0始まり）は `s器具+(i−2.5)×3.6`。指定側は奇数添字で開始側を反転。1列目の開始は左、2列目は右。各基準点で `0.48≤(x−2×lane)×指定側≤1.35` かつ `y<0.25` | 最初の4手前から最後の1.6先まで専用入力。左／右は中心±0.9への指定で連打しても重ならない。ジャンプ禁止。列中は各ポールの成否を記憶し、出口で6本全部成功なら1クリア。途中に何回誤りがあっても1列1ミス、「ポールN本目をミス」は最初の失敗番号 |
| Aフレーム | 半長4.8、幅1.9、高さ2.15。入口 `s器具−4.8` 時点の横距離0.68以下で板に乗り、接地して入れば成功予定。入口の合否を出口 `s器具+4.8` で1度採点 | 乗れば中央へ固定。外から途中合流して成功にはならない。区間中、左右と新規ジャンプを抑止し、停止・再開は可。「坂の入口を外れた」または「坂の入口でジャンプ」。接地高は `2.15×max(0,1−abs(s−s器具)/4.8)` |
| シーソー | `α=asin(0.235)`、長さ8、幅1.2、板厚0.12、支点高0.95。入口 `s器具−4cosα` で横距離0.48未満かつ接地して板に入る。中央付近で下入力して保持→傾く→再開→反対端で1採点 | 入口失敗「シーソーに乗れず」、止まり損ね「停止位置を通過」。乗っている間は左右とジャンプを抑止。自動回復で止められてもタップ再開で完走可能 |

**シーソーの状態遷移。** `idle` で入口を横切る。失敗なら `missed` を経て出口でミス。成功なら `approach` で中央に固定し、そのステップ内で入口より先の移動量を `4.2/11.25` 倍に補正する。中央−0.7より手前で下入力すると犬だけが止まる。タップで進み直せる。中央−0.7以降で上限+1に達する前に下入力すると `hold`。未停止で+1に達すると位置を+1に揃え、自動停止、`failed=true` として `hold` へ。「止まり損ね」と表示する。

`hold` で0.35秒、その後 `tipping` で0.85秒。`u=clamp(elapsed/0.85,0,1)`、板の角度は `α×(1−2u²(3−2u))`。待ち・傾きの間はタップを受け付けない。傾き終わって `ready` の合図後、タップで `exit` に進む。出口 `s器具+4cosα` に達した時に `exit` かつ失敗フラグなしなら成功し、`done`。板の接地高は `max(0,0.95+(s−s器具)tan(角度)+0.12/(2cos(角度)))`。停止中も板は動くが、競技全体の一時停止では板の時計も止まる。

### 5.5 表示用時計、自己ベスト、リセット

- 競技中の時計は `tenths=round(seconds×10)` としてから `floor(tenths/600)` 分、`floor(tenths/10)%60` 秒、`tenths%10` の順に表示。59.94秒は `00:59.9`、59.96秒は `01:00.0`。結果画面とコース一覧は `time.toFixed(2)+'秒'`。
- `finishRecord(courseId,time)` へ渡す値はレースが相棒の `time`、アジリティが `total`。未知のコース、非有限または0以下は `Error('Invalid course result')`。前回ベストを読み直し、実値が短い方を保存。比較ラベルの差だけは `h(t)=round(Number(t.toFixed(2))×100)` で計算する。
- 前回なしは「初記録」。`h(今回)−h(以前)` が負なら「X.XX秒短縮」、正なら「ベストまで X.XX秒」、0なら「自己ベストタイ」。たとえば38.204→38.201秒は保存値を改善しつつ、表示はタイ。28.24秒のベストに対して28.01秒＋1ミス＝33.01秒は「ベストまで 4.77秒」。
- リトライと一時停止時の「最初から」は `sim.reset()`、表示側の取得物・器具のリセット、カメラ位置・追従距離・フレーム時刻・フィードバックの初期化を経て `start()`。相棒とコース別ベストを保ち、走行の計測・位置・CPU・ゲージ・取得済みID・器具結果は新規にする。次コースは旧コントローラを `dispose()` 後、新しいコースを `ready` でマウントする。

### 5.6 描画・カメラ・通知イベント

コース中心線は直線と円弧を連結する。向き `h` の直線では進行方向 `(sin h, −cos h)`、横への変位は `(cos h, sin h)×x`。犬とカメラの注視点が同じ横位置・向きを共有する。各キャラクターの `phase` は進んだ距離に連動し、対角の脚を組にして接地面に足を合わせる。ジャンプ時は脚をたたみ、斜面と板では地面の高さ・角度を反映する。`prefers-reduced-motion` 時は顔・耳・しっぽの装飾動作、胴の揺れや傾き等を抑える。

通常の背後距離は6、注視の先読み10、高さの基準2.8。公園では縦横比に応じて目標距離 `clamp(3.58/aspect,6,8.65)`。トンネル前22から出口後まで近接度を補間し、近接時は距離4.85・高さ1.26・注視高0.77に寄せる。出口の横移動ではズームと追従距離を連動して屋根の側面を避ける。他のコースのトンネルでは距離4、高さ1.15、注視高0.65に寄せる。丘では `aFrameCameraLift` に接地高を渡し、頂部と裾で上下速度を滑らかにする。斜面で犬が止まれば同じ高さで待つ。

`drainEvents()` はキューを一度取り出して空にする。共通は `go,finish`。レースでは `treat{id},ready,dash,hit{reason?},turn-wrong{direction},turn-armed{direction},turn-missed{direction},turn-done{direction}`。ここで `ready` はゲージ満タン通知で、競技の `status='ready'` とは独立。アジリティは `obstacle-clear{id},obstacle-miss{id,reason},seesaw-recover`。取得物を消す処理、短いテキスト、結果画面と保存は描画コントローラが受け持つ。

## 8. 切り出しやすさと既存アプリへの組み込み

### 8.1 専用ページとして組み込む（全機能の移植）

元の配信構成に最も近い経路で、ホストのフレームワークを問わない。以下の `/games/wan-run/` は移植先で決める**配置例**。

1. ZIPの `source/dist/` の**中身**をホストの静的アセット領域の `games/wan-run/` に配置する。例として `public/games/wan-run/index.html`、`public/games/wan-run/app.js`、`public/games/wan-run/assets/three.module.js` が並ぶ。大文字小文字・ファイル名・階層を維持する。最初は全体をコピーすると比較画面も利用できる。
2. `/games/wan-run/` から同ディレクトリの `index.html` を返す。末尾の `/` または明示的な `index.html` を使い、CSSやJSをホストのSPA用HTMLへ書き換えない。`.js` はJavaScriptのMIMEタイプ、`.css` はCSSとして配信する。ビルドツールでゲームのモジュールを変換する必要はない。
3. 既存アプリのメニューに通常リンクを足す。ページを独立させるとゲームの `body`、全画面CSS、Canvas、URLハッシュ、履歴、キーボードのフォーカスが専用Documentに収まる。

```html
<a href="/games/wan-run/">わんランで遊ぶ</a>
```

4. 同じページ枠に収める要件なら、ホストの専用画面にiframeを置く。ゲーム領域を十分な高さにする。以下は全面表示の例で、ホストの固定ヘッダーがあればその高さを差し引く。

```html
<iframe
  src="/games/wan-run/index.html"
  title="わんラン　レースとアジリティ"
  style="display:block;width:100%;height:100dvh;border:0"
></iframe>
```

5. 初回アクセス、選択、レース・アジリティの完走、アプリ切替、再読み込みとベスト復元を第9章で照合する。ホストでゲームから戻る専用ボタンが要る場合は親画面に置く。ゲーム内の「コース選択」はわんラン内の一覧に戻る。

**URLと履歴。** 通常のフラグメントなしは相棒画面。`#mode` はモード選択、`#course` は確定モードがあればコース選択、なければモード選択。`#race`／`#agility` は確定モードが一致しアクティブなコースが有効なら競技の開始待ちへ、不一致時は確定モードの有無でコース／モード選択に戻す。一般の未知ハッシュは相棒画面。`?play=hill-field` のような有効IDはモードとコースを確定・保存し、`play` をURLから消してモードのハッシュに置換する。`?trial=poodle` 等の有効IDは初期表示の犬と毛色0を一時指定、スカーフは保存値を使用し、次の相棒保存時に `trial` を取り除く。無効IDに専用画面は出ない。次のコースへの移動は同じゲームハッシュ内で表示を入れ替える。走行中の再読込では同じ場所のレースは復元されず、開始待ちに戻る。

**保存先の移行。** 同一オリジン・同じストレージ区画・同じキーならゲームのパス変更だけで既存記録を読める。元公開ドメインと別のドメインでは、同じブラウザでも新サイトから旧サイトの `localStorage` を読めない。既存プレイヤーの記録移行が必要なら、旧オリジン側に明示操作のエクスポート、移植先に型・正値・許可IDを検証するインポート等を別途実装する。記録を統合する場合は各コースの有効な最短値を採用する。現在のゲームにはエクスポート・インポートUIはない。同じサイトで複数アカウントが交替する環境では現状はそのブラウザ内で共有される。

### 8.2 ホストの画面に直接マウントする（部分利用）

| 移植単位 | そのまま使える部分 | 接続または変更する部分 |
|---|---|---|
| ルール・位置計算 | `RaceSimulation`、`AgilitySimulation`、`gestureAction`、広場・カーブ・砂地・器具の数式。DOMやThree.jsを用いず更新可能 | ホストが入力を `left/right/jump/brake/dash` に変換し、`start/step/pause/resume/reset/drainEvents` を駆動。既存ループとゲーム側ループを二重起動しない |
| 相棒・景色 | `makeCompanion,poseCompanion,poseLegs,makeCourseScene,makeRaceTrack,makeAgilityField` と個別造形 | 同じThree.jsオブジェクト体系でシーン、カメラ、ライトを用意。テクスチャや外部の犬モデルを準備する工程は不要 |
| 競技UI単位 | `mountRace` はレース・アジリティ両方の入口。結果保存・再挑戦・自動一時停止・独自の走行ループを内包 | 実DOMのコンテナ・有効な犬種オブジェクト・毛色添字・スカーフ色・コースとモードを渡す。出口と次コースをホストに接続し、画面を外す際に `dispose()` |
| 選択UIを含む全体 | 全画面HTML、犬・モード・コース・ダイアログ、記録表示は独立ページならそのまま | `app.js` はimport時に即起動。ホストDOMへ直結する場合は `mount/unmount` 形式へ整理しDOM参照・CSS・ルーティングを局所化 |
| ストレージ | `courseBest,finishRecord,formatTime,formatRaceClock` と保存キー | 保存先の実参照は `app.js` と `course-records.js` の2か所。ユーザー別・非同期DBに置換する場合は起動前の復元、完走時の書込と失敗時の一時ベストを実装。複数書込では最短値を原子的に採用 |
| 運用付属物 | `tests/`、レビュー画面、履歴 `PROJECT_NOTES.md` | ゲーム本番の入口には不要。比較ページと旧コードはまとめて独立させる。`.openai/hosting.json` は元サイト固有 |
| ゲーム結果の通知 | `race-game.js` の `result()` には `sim.result` と `finishRecord` の戻り値が揃う | 親に結果が必要ならここへ任意の `onFinish` 等を追加。現行の公開引数にはない。保存先の競合を避け、ホスト側とゲーム側で同じ完走を二重登録しない |

**`mountRace` の契約。** `container: HTMLElement`、`breed: breeds[]の1要素`、`coat: 0|1|2`、`scarfColor?: CSS色文字列`、`onExit: () => void`、`onNextCourse?: (id) => void`、`mode?: 'race'|'agility'`、`courseId?: string`。`mode` の既定は `race`、コース既定はレースが `park`、アジリティが `first-field`。`scarfColor` を省くとモデル側の犬種別色になるので、通常の相棒には `scarfOption(...).color` を渡す。戻り値は `{mode,courseId,pause(),dispose()}`。`onNextCourse` がなければ次コースボタンは出ない。`onExit` は競技場面を閉じるコールバックで、呼び出し元が実際に破棄・遷移を行う。

以下は独立したホスト画面から競技だけを呼ぶ最少例。`#wan-run-slot` を空のコンテナとして置き、2つのゲームCSSを元の順に読み込んでおく。ここでは導線の例として「公園」で初期の相棒を使用する。既存アプリの選択画面と組み合わせる場合は `openCourse` の引数と相棒選択値をアプリから渡す。

```js
import { mountRace } from "/games/wan-run/race-game.js";
import { breeds } from "/games/wan-run/breeds.js";
import { scarfOption } from "/games/wan-run/scarf-colors.js";

const slot = document.getElementById("wan-run-slot");
let controller;

function leaveGame() {
  controller?.dispose();
  controller = undefined;
  // この例では、わんランの通常入口に戻る。
  window.location.assign("/games/wan-run/");
}

function openCourse(courseId) {
  controller?.dispose();
  controller = mountRace({
    container: slot,
    breed: breeds.find(dog => dog.id === "pomeranian"),
    coat: 0,
    scarfColor: scarfOption("blue").color,
    mode: "race",
    courseId,
    onExit: leaveGame,
    onNextCourse: openCourse
  });
}

openCourse("park");
// SPAのアンマウント処理にも controller?.dispose() を登録する。
```

**直結時の具体的な変更箇所。**

- `app.js` は `document.getElementById/querySelector`、`document.body.dataset`、ヘッダーの `h1`、`--course-color`、`location/history` を直接扱う。`#app,#panel,#viewer,#raceRoot` 等のID、ダイアログとヘッダーをホストの既存要素と混同しない。SSRを使う場合はDOM生成後にクライアント側から初期化する。
- `style.css` の `:root,* ,html,body,main,.header,.primary` 等と `.race-root{position:fixed;inset:0;height:100dvh}` はDocument全体がゲームという前提。ページ内カードで直接使うならルートにCSSを限定し、競技面をサイズのある相対配置の親に収める。`mountRace` はコンテナの `className` と `innerHTML` を置き換えるので、ホストの見出し・ナビを含む要素は渡さない。
- 選択プレビューの `tick` は走行中も次のフレームを予約し続ける。`app.js` 全体には破棄APIがなく、選択画面の `ResizeObserver` も保持していない。SPAで繰り返し直結する場合はRAF ID・Observer・各リスナー・タイマー・モデル・rendererをインスタンスで管理し解放する。競技側の `dispose()` はRAF取消、タイマー、Observer、Document/Windowのリスナー、geometry/material、ライト、レンダラーとWebGLコンテキストの解放、コンテナ非表示まで行う。
- ホストがゲーム領域をCSSで畳む、自分のモーダルで覆う、アプリ内タブだけを切り替える場合、ブラウザの `visibilitychange` が来るとは限らない。直接組み込む場合は離脱時に `controller.pause()`、破棄時は `dispose()` を呼ぶ。iframeは専用Documentごと破棄するか、親と子の間に明示的な休止通知を実装する。通常版に親向けの `postMessage` 契約はない。
- ホストのCSP・iframe設定・埋め込み元のポリシーにより、同梱モジュール、Canvas、動的スタイル、`data:` のサムネイル、ストレージが使えるかを確認する。比較ページも提供する場合はそのimport map・インラインモジュール・子フレームの読込も確認する。公開ドメインを外部iframeで指す方法と、原本をホストから配信する方法では、依存する公開先と保存領域が変わる。

### 9.2 実装上の制約、未実装、移植時に再現しやすい問題

| 条件 | 実際に起きること |
|---|---|
| WebGL 2が使えない・競技シーンを作れない端末 | 選択画面は説明と代替表示を使える。実際の競技を2Dで遊ぶ代替モードは未実装。競技初期化は例外を捕捉するが、競技中のWebGLコンテキスト喪失から走行を復元する専用処理はない |
| ページを更新・タブを閉じる・別端末に移る | 完走したコースのベストと確定した相棒等だけが復元対象。途中の走行のセーブ、クラウド同期、複数プレイヤーのオンライン対戦、共有ランキング、成績の外部APIは未実装 |
| ブラウザストレージの拒否・削除 | その場での競技は継続。ベストの一時MapはDocumentの寿命まで。ブラウザデータ消去後に元に戻す機能はない。毛色ボタン単独の保存失敗やプレイ可能コース確定失敗など、すべての書込拒否に個別の通知が出るわけではない |
| 複数タブでほぼ同時に完走 | 結果確定時に前回値を読み直すが、`getItem` と `setItem` は一連の原子的更新ではない。ユーザー単位のサーバー保存に替えるなら、より短いタイムを確実に残す更新方式が必要 |
| 無効な `courseId`、誤ったモード／コースの組み合わせで直接起動 | シミュレーション生成が公園／初期広場にフォールバックする場合がある一方、記録処理は未知IDで例外を出す。通常入口は `canPlay(mode,id)` で既知の組み合わせだけを使う。ホストの直呼びも同じ組み合わせで起動する |
| 3D即時起動モジュールや比較用コードを既存SPAへ直接import | 選択画面はDocument全体と固定IDを前提とする。比較ページは固定入力、仮の保存値、時刻差し替えを使う。複数インスタンスやSSR、ホストのルーティング・ゲームパッド・タッチ専用ボタンへの変換は個別対応 |
| 原本の履歴を読む | `PROJECT_NOTES.md` は初期試作・将来案からの時系列。冒頭の「他コースはプレビュー」等は当時の状態。v33では全7件プレイ可能。`dist/review/vXX/` は比較のための旧実装で、本番の差し替え元は `dist/` 直下 |
| 時間と合図の境界 | 競技時計はシミュレーション時間。1フレーム0.2秒超は上限処理があり実時計からずれ得る。Aフレームの合図「位置が合った」は横差0.68未満、物理の入口成功は0.68以下。同じタイム表示でも内部精度でベストや着順が変わり得る |

### 9.3 移植後の受入試験

| 試す順 | 操作 | 合格条件 |
|---|---|---|
| 1 | 空の保存領域で通常入口を開く。犬種を仮変更→×。再度変更→決定。同じ犬の再確定、別犬への確定、毛色変更 | 初回ポメラニアン・オレンジ・青。取消は犬と毛色を復元。別犬確定は毛色0、同じ犬確定は元の毛色。左右ドラッグ・キーボードで回転し、向きリセットできる |
